# CLAUDE.md — The Unreliable Assistant → Enterprise Grade

Project guide for AI engineers (and Claude Code) working in this repo.
Source specs: `Unreliable_Assistant_MidCheck_Enterprise_Blueprint_v2.docx` (authoritative),
`SLM_Comprehensive_Guide.docx` (SLM selection / QLoRA), `Post_Hardening_Engineering_Audit_Report.docx` (claimed outcomes — treat as targets, never as evidence).
Spec gaps, conflicts and the decision taken for each: `docs/GAPS_AND_ASSUMPTIONS.md` (read before changing behaviour).

## Hard rules (from the blueprint)
1. **`design.md` (Gate 1) and `docs/workflow_orchestration.png` (Gate 2) come before application code.** Do not change architecture without updating `design.md` first.
2. Every tool call goes through `ToolExecutionHarness` (strict Pydantic v2 → regex auto-repair → RBAC tier → UUIDv4 idempotency). No direct tool calls from agents.
3. Tool integrations are MCP servers (JSON-RPC 2.0): `mcp-hybrid-rag`, `mcp-state-store`, `mcp-graphify-vault`. Cross-cutting behaviour is a pluggy plugin (`src/unreliable/plugins/`), never inlined in the core.
4. ReAct loop is bounded: `max_iterations=5`, `per_step_timeout=120ms`, `total_loop_budget=450ms`, no recursive self-calls without state mutation. Circuit breaker trips at ≥2 identical `(tool, canonical_args_hash)` failures.
5. Tier 3 (`TIER_3_MUTATE`) actions NEVER execute inline: write `PENDING_APPROVAL`, wait for reviewer approval. Enforcement must be 100%.
6. Tenant isolation: `tenant_id` in every SQL query and every cache key (`SHA256(tenant_id:user_id:norm_query)` under a per-tenant prefix). A cross-tenant leak is a release blocker.
7. Zero raw PII persisted (redact before cache/audit/DB). Audit log is SHA-256 hash-chained; MCP manifests are HMAC-signed.
8. When cross-encoder top score < threshold (0.42 sigmoid) → deterministic abstention, no LLM call.
9. **Never report a KPI as passed without a measurement.** Scorecard statuses are `PASS`, `FAIL`, `PARTIAL` (threshold met only at reduced scale / proxy metric) or `NOT_MEASURED`. The 50K-VU and 1-hour-soak KPIs cannot be fully verified on the dev box — say so.

Hand-over docs: `docs/GPU.md` (GPU run), `docs/KNOWN_ISSUES.md` (open KPIs). Env: `MODEL_PROFILE=dev|spec|gpu`, `DEVICE=auto|cpu|cuda`, `LLM_BACKEND=extractive|anthropic`, `RAG_ADMIT`, `LATENCY_SCALE`.

## Environment & commands
Always use the repo venv (`.venv`, Python 3.14 — spec says 3.11, see GAPS G-04).
```bash
source .venv/bin/activate && pip install -r requirements.txt
python scripts/build_corpus.py          # vault + golden/red-team/etc. datasets (deterministic, seed 7)
python scripts/build_graph.py           # graphify build ./src ./knowledge_vault → graph.json
python scripts/render_workflow.py       # Gate 2 PNG (300 DPI)
uvicorn unreliable.api:app --port 8000  # API (spawns MCP servers); needs PYTHONPATH=src
python mcp_servers/state_server.py      # streamable-http MCP on :8081
streamlit run app.py                    # workbench
pytest -q                               # unit/integration tests
python evals/run_kpis.py                # all measurable KPIs → reports/kpi_report.json
bash load_tests/run_load.sh             # k6 (+JMeter) scaled run; VUS env var sets scale
```
External tools (k6, JMeter, Graphviz-WASM) live in `~/tools` (no sudo on the dev box).

## Conventions
- Pydantic v2 everywhere at boundaries; `extra="forbid"` on tool inputs.
- Async I/O on the request path; CPU-bound model inference runs in bounded executors (bulkheads: rag=64, db=128, llm=256).
- Config via `src/unreliable/config.py` (env-overridable); no magic numbers elsewhere. Model profile `MODEL_PROFILE=dev|spec` (dev = bge-small + MiniLM reranker for CPU; spec = bge-large + bge-reranker-v2-m3).
- Datasets are generated, deterministic and committed; regenerate rather than hand-edit.
- A change to retrieval, triage, harness or plugins must be followed by `pytest -q` and `python evals/run_kpis.py`; do not weaken a threshold to make a KPI pass — fix the system or report the failure.
