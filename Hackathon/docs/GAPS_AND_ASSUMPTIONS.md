# Gap Analysis: missing / conflicting information in the three specs

Result of the document review requested before implementation. None of the gaps blocks the build, so each was
resolved with an explicit, reversible assumption (column "Decision"). Items marked **RISK** change how results should be read.

| ID | Conflict | Resolution |
|----|----------|------------|
| C-01 | Triage latency `< 30 ms` (Gate 2 diagram) vs `<= 25 ms` (Gates 6/7, KPI-05, audit report). | 25 ms is the KPI; 30 ms is the hard timeout fallback. |
| C-02 | "3-stage" RAG (blueprint) vs "4-stage" (audit report: BM25, dense, RRF, rerank). | Same pipeline: 2 retrievers → fusion → reranker. Called "3-stage" with RRF as the fusion step. |

| C-05 | p50 target: k6 `p(50)<250` vs KPI-31 `<= 240 ms`. | KPI-31 (240 ms) is stricter and is used. |

## C. Defects in the supplied snippets
- `SLM_Comprehensive_Guide` QLoRA script: `Dataset.from_dict` mixes list and string columns (`"output"` is a bare string) → raises; EOS appended twice (`<|im_end|>` + `tokenizer.eos_token`); `TrainingArguments`-style kwargs (`max_seq_length`, `dataset_text_field`) are removed in recent TRL (`SFTConfig`). Fixed version: `training/qlora_finetune.py` (not executed: no GPU).
- k6 script: `r.json('tenant_id')` throws on non-JSON error bodies, masking the real failure; fixed with a guarded parse. `sleep(1)` with 50K VUs yields ≤50K RPS offered load, so KPI-35 (≥8,500 RPS) is a lower bound check.
- `mcp_config.json`: `state-store` timeout absent while others have `timeout_ms`; added 150 ms for consistency.

## D. Measured hardware reality (added during build)
- **G-17 update.** On this 4-vCPU 2.2 GHz Xeon, an INT8 MiniLM-L6 cross-encoder costs ≈ 15–17 ms per (query, passage) pair, so the spec's "32 pairs in < 45 ms" is physically unreachable without GPU (INT8 gave only 1.4× over fp32). Decisions: (a) reranker is INT8-quantised (ADR-2, `scripts` auto-quantise on first load); (b) dev profile reranks the RRF top-**8** (`RERANK_POOL`, spec = 40) with `max_len` 160; (c) runtime timeouts (`per_step`, loop budget, MCP, rerank) are multiplied by `LATENCY_SCALE` (dev 4×: step 480 ms, loop 1.8 s, MCP 600 ms) so the system doesn't permanently degrade; (d) **KPI thresholds are never scaled** — KPI-09 and the cache-miss e2e latency KPIs are expected to FAIL/PARTIAL on this box and are reported as measured.

- **C-10 resolved.** Dev profile (INT8 MiniLM) threshold = 0.30, calibrated on the golden *dev* split (lowest answerable gold score 0.34; non-entity negatives ≈ 0.0). Spec profile keeps 0.42. Two extra deterministic gates were added after eval findings: entity/qualifier grounding (SKU/SUP IDs, `Tier X`) and an unsupported-terms gate (>=2 vault-unknown terms, >=35 % of content words, <50 % lexical coverage).
